## 阶段 0：环境搭建

**目标**：一条命令可运行的开发环境 + 固定的目录骨架。

1. 沿用上级目录已有的 `.venv`（pandas/openpyxl 已装），补装深度学习依赖：
   - `torch`（CPU 版即可，数据规模用不上 GPU）、`scikit-learn`（注：Python 3.14 无 pyarrow/pyyaml，用 CSV + JSON 替代，无需安装）、`matplotlib`、`openpyxl`；
   - 全部写入 `v6.0/src/requirements.txt`，新机器 `pip install -r requirements.txt` 可复建。
2. 初始化目录骨架（与计划书 §6 一致）：
   ```
   v6.0/src/{data,features,models,anomaly,viz}
   v6.0/configs/          # 实验 JSON
   v6.0/data/clean/       # 清洗后数据（程序生成，不手改）
   v6.0/results/<exp>/    # 每次实验：metrics.json + 预测csv + 图
   v6.0/figures/
   ```
3. 建立两个全局约定（写进 `src/common.py`）：
   - `set_seed(seed)`：固定 torch/numpy/random，所有实验入口调用；
   - 路径常量：`ORIDATA_DIR = ../OriData`、`ORIDATA2_DIR = ../OriData2` 等集中在 `configs/paths.json`，代码里不出现硬编码路径。

**验收**：`python -c "import torch, sklearn, pandas"` 通过；目录骨架齐全；`requirements.txt` 与环境一致。

## 阶段 1：数据管道（一次写好，全程复用）

**目标**：把 OriData / OriData2 的杂格式变成一张干净的统一长表。

按顺序实现四个脚本（`src/data/`）：

1. `parse.py` —— 解析
   - TXT：GBK 读入，两列 `YYYYMMDD value`，文件名拆出台站/分量/测项码；
   - 元数据表：`B区域_云南省.xlsx` 是"单列 CSV 文本"，按逗号拆分并**去掉值内引号**后建映射表；
   - OriData2 xlsx：兼容两种日期格式（`20250101` / `2026-06-09`）与多种表头名（时间/日期、数值/值/数据）。
2. `clean.py` —— 清洗：`999999`→NaN；连续缺失 ≤7 天线性插值、>7 天留空；缺失率 >20% 打 `low_quality`；日值序列按日重索引，暴露断档。
3. `merge.py` —— 与元数据 join 出台站名/测项名；同台站同测项多分量按测点编号区分；输出 `data/clean/long.csv`（station_id, station_name, item_code, item_name, date, value, quality_flag）。
4. `split.py` —— 生成实验数据集：**按时间顺序**前 80% 训练 / 后 20% 测试；输出每个台站-测项组合的元信息（起止日期、样本量、缺失率）供选台用。

**产出**：`data/clean/long.csv` + 台站×测项数据质量一览表（直接进论文附录）。
**验收**：39 台站全部解析无报错；抽查 3 个文件数值与原文件一致；西昌32井 2015–2026 序列完整无异常断档；重跑幂等（结果不变）。

## 阶段 2：基线复现（管线正确性的证明）

**目标**：用最简单的模型跑通"训练→预测→评估"全链，并用文献数值做健全性检查。

实现顺序（由简到繁，每个都是独立可跑脚本）：

1. 持久性预测（今天=昨天）——评估管线的下界；
2. RF（文献配置：100 树、最大分裂 100、最小叶 5 样本）；
3. 单独 LSTM（文献配置：1 层 LSTM + 2 全连接，60 天窗，dropout 0.3，Adam）；
4. LSTM-RF 级联（LSTM 隐状态输出 → RF 回归）——文献最优方法。

**健全性检查点**：文献测试集 R² 量级为 RF ≈ −2.38、LSTM ≈ 0.58、LSTM-RF ≈ 0.85（MAPE 5.08% / 1.26% / 1.18%）。我们在西昌32井上的复现**不必数值相同**（不同井不同数据），但**相对排序应当一致**：RF 明显崩、LSTM 过拟合下降、LSTM-RF 最好。排序不符说明管线有 bug，必须排查后才能继续。

**产出**：`results/baseline_<model>/`（指标 json + 预测对比图）。
**验收**：四个基线全部完成、排序与文献一致、评估指标函数与文献公式逐项核对过。

## 阶段 3：CNN-LSTM 与消融实验（项目的核心创新）

**目标**：回答"水位信息能否提升水氡预测"——联合建模必须有实证。

1. `models/cnn_lstm.py`：Conv1D(64,k3)→Pool→Conv1D(32,k3)→LSTM(64)→Dropout(0.3)→Dense(1)，输入形状 [样本, 60, n_vars]；
2. 三组消融（同一套划分、同一套超参）：
   - A：仅水氡 → 水氡（单变量基线）
   - B：仅水位 → 水位（单变量基线）
   - C：水氡+水位 → 水氡（联合，主检验）
3. 每组 5 个随机种子，报均值±标准差；C 与 A 做显著性比较（ paired 比较即可）；
4. 小规模网格搜索（hidden {32,64,128} × kernel {3,5} × 窗口 {30,60,90}），JSON 配置驱动，结果归档；
5. 误差分解：按月/季节统计误差，看联合增益来自哪些时段（预期雨季水位信息更有用）。

**产出**：消融对比表（论文核心表）+ 预测对比图。
**验收**：C 优于 A（或如实记录不显著）；每组结果可复现（同种子同结果）；结论不依赖单次运行。

## 阶段 4：残差 LOF 异常检测

**目标**：从最优模型的残差里提取候选异常事件。

1. `anomaly/lof_detect.py`：sklearn `LocalOutlierFactor(novelty=True)`，输入 = 标准化残差（以及原始标准化序列作对照）；
2. k 值策略函数化：基准 √n，界于样本量 1%~10%；残差小 k（5~25）、原始序列大 k（20~60）、水位中等 k（10~30）；
3. 阈值：LOF 得分分位数，默认 0.987，敏感性分析扫 {0.98, 0.985, 0.987, 0.99, 0.995}；
4. `event_aggregate.py`：间隔 ≤3 天的异常点合并为"异常事件"，输出事件表（起止日期、峰值得分、持续天数、所属序列）；
5. 对每个异常事件，回查原始值曲线形态（突跳/趋势/低值），自动打形态标签。

**产出**：四条序列（水氡残差、水氡观测、水位、水温/汞）各自的事件表 + 多参数异常得分叠加图（对齐文献图 9）。
**验收**：敏感性行（k×分位数网格）跑完并落盘；事件表格式统一；手动抽查 2–3 个异常事件与原始曲线吻合。

## 阶段 5：多参数互证与干扰排除（从"候选异常"到"前兆结论"）

**目标**：把阶段 4 的事件表筛成可信的构造指示异常。三道关，逐关留痕：

1. **参数互证**：不同序列的异常事件时间重叠（重叠即记重合），输出重合组表——只有被 ≥2 条独立序列印证的事件才进入下一关（文献设计）；
2. **干扰排除**：每个重合事件与同期降水/气温/气压标准化曲线对比，并检查标定检修记录；能用气象/仪器/人为解释的标记"干扰异常"（预期雨季低值事件大多在此被排除）；
3. **震例对应**：剩余事件与地震目录（M≥4，含震中距）做时间对应（事件后 N 天窗口内有无地震）；有条件时叠加钻孔应变同期变化。

**产出**：异常事件台账（编号、时段、形态、互证序列、干扰归因、震例对应、最终判定）——这就是论文的结论表。
**验收**：台账覆盖全部候选事件（排除的也要留记录）；判定理由可追溯到具体数据文件。

1. **原始数据不可变**：`../OriData`、`../OriData2` 只读，一切清洗产物进 `data/clean/`；
