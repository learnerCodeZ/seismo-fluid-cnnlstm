## 1. 任务定义

两阶段流水线，均为经典 ML 任务形态：

```
阶段一（回归）：时序预测
  输入  X = 过去 60 天的多元流体序列窗口      形状 [batch, 60, n_vars]
  输出  ŷ = 下一时刻水氡浓度（标量回归）

阶段二（无监督异常检测）：
  输入  r = y_true − ŷ（预测残差序列）
  输出  LOF 得分 + 二值异常标记（分位数阈值）
```

- 监督信号只来自序列自身（自回归），**不需要异常标签**——这是选无监督路线的原因：震例少、异常点无标注，监督分类不可行。
- 地震目录（发震时刻、震级、震中距）只用于**结果分析阶段**的异常-地震对应，不进入训练。

## 2. 数据管道

### 2.1 原始数据现状

| 来源 | 格式 | 内容 |
|------|------|------|
| `OriData/`（127 个 TXT） | GBK 编码，两列 `YYYYMMDD value`，文件名 `台站_分量_测项码_日` | 云南 39 台站日值，缺测码 `999999`，覆盖 2025-01-01～2026-06-11 |
| `OriData/B区域_云南省.xlsx` | 单列 CSV 文本，逗号分隔 | 台站代码↔台站名、分量编码↔测项名元数据 |
| `OriData2/**/*.xlsx` | 双列表（时间列格式混杂：`20250101` / `2026-06-09` 混用） | 整理后的台站数据，含西昌32井 2015–2026 长序列 |

### 2.2 处理步骤（对应 `src/data/`）

1. **parse**：TXT/Excel 统一解析 → 长表；日期解析兼容两种格式；GBK 显式声明；
2. **clean**：`999999` → NaN；连续缺失 ≤7 天线性插值，>7 天保留 NaN；缺失率 >20% 的序列打 `low_quality` 标记；
3. **merge**：与元数据表 join，补全台站名/测项名；同一台站同一测项多分量文件按测点编号区分；
4. **transform**（按文献方法）：降水累积→日值，气温/气压算术平均→日值（仅当获得小时值数据时）；
5. **detrend / deseasonalize / z-score**：LOF 输入用标准化序列，模型输入用原始（或 MinMax）序列，两套并存不混用；
6. **输出**：`data/clean/long.csv`（Python 3.14 无 pyarrow，CSV 替代），五列 schema：
   `station_id, station_name, item_code, item_name, date, value, quality_flag`

> 明确目标：**解析、清洗逻辑只写一次**，全部台站共用；新增数据（回溯、气象）零成本接入。

## 3. 模型设计

### 3.1 CNN-LSTM 主模型

```
Input [60, n_vars]
  → Conv1D(filters=64, kernel_size=3, padding='same') + ReLU      # 局部突变特征
  → MaxPool1D(2)
  → Conv1D(filters=32, kernel_size=3, padding='same') + ReLU
  → LSTM(units=64, return_sequences=False)                         # 时序依赖
  → Dropout(0.3)
  → Dense(32, ReLU) → Dense(1)
```

- 优化器 Adam，损失 MSE，early stopping（patience=10，监控 val_loss）；
- 滑窗 60 天、步长 1 天（对齐文献设置，保证可比）；
- 以上为首版配置，具体超参以小规模网格搜索为准（hidden units {32,64,128}、kernel {3,5}、窗口 {30,60,90}）。

### 3.2 基线模型（对照集合，全部同窗长同划分）

| 模型 | 用途 |
|------|------|
| 持久性预测（naive：昨天=今天） | 下界 |
| RF（文献同款：100 树、max_depth=100、min_leaf=5） | 复现文献单一模型 |
| 单独 LSTM | 复现文献单一模型 |
| LSTM-RF 级联（LSTM 隐状态 → RF） | 复现文献最优方法 |
| **CNN-LSTM（本项目主模型）** | 待检验对象 |

文献已给出 RF/LSTM/LSTM-RF 的量级表现（测试集 R² 分别为 −2.38 / 0.58 / 0.85），可作为我们实现的**健全性检查**：复现结果同量级则管线无误。

### 3.3 消融实验（核心实验，检验"联合建模"）

| 组 | 输入变量 | 输出 | 检验假设 |
|----|----------|------|----------|
| A | 水氡 | 水氡 | 单变量基线（=文献并行式） |
| B | 水位 | 水位 | 单变量基线 |
| C | 水氡 + 水位 | 水氡 | 水位是否带来预测增益 |

- 每组重复 ≥5 个随机种子，报均值±标准差（时序模型方差大，单次结果不可信）；
- 数据划分：按时间顺序切分（如前 80% 训练 / 后 20% 测试），**禁止随机打乱划分**（时序泄漏）；
- 附加分析：分季节/分时段误差分解，确认增益来源（如雨季水位信息更有用）。

### 3.4 评价指标

RMSE、MAE、MAPE、R²（sklearn 手写实现，与文献公式逐一对齐）；测试集与训练集指标分列并报差值（文献即如此呈现，用于判断过拟合）。

## 4. 异常检测模块（`src/anomaly/`）

```python
from sklearn.neighbors import LocalOutlierFactor
lof = LocalOutlierFactor(n_neighbors=k, novelty=True)
scores = -lof.score_samples(X)      # 分数越大越异常
threshold = np.quantile(scores, 0.987)
anomalies = scores > threshold
```

- 输入选择：残差序列（主）与原始标准化序列（对照），分别检测；
- **k 值策略**（照文献思路实现为函数）：基准 √n，上下界 = 样本量的 1%~10%；残差用小 k（5~25）、原始序列用大 k（20~60）、水位/水温用中 k（10~30）；
- **阈值敏感性分析**：分位数 ∈ {0.98, 0.985, 0.987, 0.99, 0.995}，输出异常点集合的稳定性对比；
- **事件聚合**：相邻异常点间隔 ≤3 天合并为一个"异常事件"（文献即按事件组统计，7 组、12 个点），输出事件表：起止日期、峰值得分、持续天数；
- 多参数互证的量化：计算不同序列异常事件的**时间重合率**（事件区间重叠即记重合），替代肉眼比对。

## 6. 工程组织

```
src/
├── data/        # parse / clean / merge / split（一次性管道，幂等可重跑）
├── features/    # 滑窗构造、标准化、（可选）小波特征接入 v5.0 结果
├── models/      # cnn_lstm.py, baselines.py, train.py, evaluate.py
├── anomaly/     # lof_detect.py, event_aggregate.py, sensitivity.py
└── viz/         # 图表脚本
configs/         # 实验配置 JSON（Python 3.14 无 pyyaml，JSON 替代 yaml）
requirements.txt # torch, scikit-learn, pandas, matplotlib, openpyxl（CSV+JSON 方案，无 pyarrow/pyyaml）
```

工程约定：

- 全流程由配置驱动（JSON），改实验 = 改配置不改代码；
- 固定 `torch.manual_seed` / `np.random.seed`，实验可复现；
- 每次实验输出 `results/<exp_name>/`：指标 json + 预测 csv + 图，杜绝结果散落；
- 与 v5.0 衔接：小波系数 CSV 作为可选特征通道读入 `features/`，不做硬耦合。

## 7. 技术风险（仅限实现层面）

| 风险 | 对策 |
|------|------|
| 日值序列仅 ~1.5 年，训练样本少（≈450 窗口） | 优先用西昌32井 11 年序列开发调试；滑动起点增强样本量 |
| 多站点数据格式不一（时段/单位/缺测差异） | 管道层抽象 + quality_flag，模型只消费 clean 层 |
| LOF 结果对 k/阈值敏感 | 固化敏感性分析脚本，结论报告必须附稳定性结果 |
| 自回归滚动预测误差累积（文献已暴露） | 短窗多步评估 vs 单步评估分开报告，明确适用范围 |
