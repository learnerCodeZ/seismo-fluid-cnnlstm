> 项目：基于 CNN-LSTM 的巧家地震震前水氡-水位双流体联合建模与异常识别

---

## 一、项目做了什么（一句话）

用 CNN-LSTM 神经网络预测水氡浓度，用预测残差做异常检测，再通过气象干扰排除和地震目录对应，识别出可能与地震相关的震前异常信号。

| 数据 | 来源 | 时间 | 用途 |
|------|------|------|------|
| 西昌32井水氡日值 | OriData2（老师提供） | 2015-01~2026-05（11.3年） | 方法主战场 |

| 云南39台站流体日值 | OriData（地震局台网） | 2025-01~2026-06 | 空间对照 |

### 3.2 辅助数据

| 数据 | 来源 | 用途 |
|------|------|------|
| 西昌气象三要素日值 | OriData3（气象局） | 干扰排除（排除雨季假异常） |
| 地震目录（819事件） | OriData3（USGS API，公开） | 震例对应（异常后90天内有无地震） |

### 3.3 数据格式陷阱（踩过的坑）

1. **GBK 编码**：OriData TXT 和 OriData3 气象 CSV 都是 GBK，不是 UTF-8
2. **999999 缺测码**：气象数据的 9999/32766 也是缺测码，不是真实值
3. **降水单位混用**：2010-2019 是 0.1mm，2020 起是 mm，需 ÷10 统一
4. **元数据表是伪 xlsx**：B区域_云南省.xlsx 实际是单列 CSV 文本，需按逗号拆分
5. **OriData2 日期格式混杂**：20250101 和 2026-06-09 两种格式混用
6. **小时值 TXT 是宽表**：53123 的 `_时` 文件是每行一天+24 列，不是两列

## 四、技术路线详解

### 4.1 总体设计

```
原始数据 → 数据管道 → 滑窗特征 → CNN-LSTM 训练 → 预测残差 → LOF 异常检测 → 事件聚合 → 干扰排除 → 震例对应
```

### 4.2 为什么选 CNN-LSTM

| 方法 | 优点 | 缺点 |
|------|------|------|
| RF（随机森林） | 简单、可解释 | 无时序建模能力，只能做"年变复制" |
| LSTM | 时序建模强 | 对局部突变反应慢，容易平滑掉 |
| LSTM-RF（文献方法） | LSTM 提特征 + RF 回归 | 两段式，无法整体优化 |
| **CNN-LSTM（本项目）** | CNN 抓局部形态 + LSTM 抓趋势，端到端训练 | 可解释性弱（用消融实验补） |

CNN 的卷积核是显式的局部形态提取器——它学到的是"什么样的连续几天的形态有意义"（突跳、阶变、短时起伏）。这正是地震前兆最需要抓的模式。

### 4.3 为什么走无监督路线

- 震例少（只有几个 M≥5 地震），无法标注"哪里是异常"
- 监督分类需要正负样本，我们没有
- LOF 的"局部密度比较"机制能识别"全局正常、局部异常"的微弱信号
- 预测残差把"原始序列异常检测"转化为"残差异常检测"，提高灵敏度

### 4.4 三道关验证（从"候选异常"到"前兆结论"）

```
候选异常事件
  ↓ 关口①：多参数互证（≥2条独立序列印证）
  ↓ 关口②：气象干扰排除（降水/气温/气压对比）
  ↓ 关口③：震例对应（90天窗口内有无 M≥4 地震）
  ↓
最终判定：构造指示异常
```

## 五、每个阶段的关键决策

### 阶段 0：环境

| 决策 | 理由 |
|------|------|
| 用 CPU 不用 GPU | 数据/模型规模迷你（5万参数），单次训练分钟级，GPU 杀鸡用牛刀 |
| CSV 替代 parquet，JSON 替代 yaml | Python 3.14 太新，pyarrow/pyyaml 无发行版 |
| 路径配置集中在 paths.json | 原始数据在中文路径，代码零硬编码 |

### 阶段 1：数据管道

| 决策 | 理由 |
|------|------|
| OriData2 去重限同测项大类 | 冒烟测试教训：水氡(~22.8 Bq/L)和水温(~22.x ℃)数值区间撞了，跨类匹配会误删 |
| 小时值先聚合为日均值 | clean 重索引到日频后，小时序列只剩零点一个读数，数据失真 |
| NaN 特征行整行丢弃，禁止插值 | 冒烟测试教训：插值补出的常数段把 LOF 得分炸到 1e9 量级 |

### 阶段 2：基线复现

| 决策 | 理由 |
|------|------|
| 用文献排序做健全性检查 | 不必数值相同（不同井不同数据），但排序必须一致：RF<LSTM<LSTM-RF |
| 验证集取训练段尾部 15% | 时序数据禁止随机打乱，防泄漏 |

### 阶段 3：CNN-LSTM

| 决策 | 理由 |
|------|------|
| Conv1D(64,k3)→Pool→Conv1D(32,k3)→LSTM(64) | 首版配置，60 天窗口对齐文献 |
| 早停 patience=15 | 防过拟合，训练自动在最优权重处停止 |
| 超参网格搜索留到后续 | 先验证方法有效，再调优 |

### 阶段 4：异常检测

| 决策 | 理由 |
|------|------|
| LOF 自参照（对残差序列自身打分） | 冒烟测试教训：训练段无残差，"用训练段当参照"是空集 |
| 工作阈值 98% 分位（非 98.7%） | 冒烟测试教训：98.7% 下低值突跳以 0.1 之差漏检 |
| 异常事件间隔 ≤3 天合并 | 对齐真实突跳的时间尺度（1-3天） |

## 六、冒烟测试抓出的 4 个 bug

| # | 问题 | 教训 |
|---|------|------|
| 1 | LOF 参照设计错误：训练段无残差 | 对残差序列自身打分（自参照 novelty） |
| 2 | NaN 特征行毒化 LOF：插值补出常数段 | 含 NaN 的特征行整行丢弃，禁止插值 |
| 3 | 连续异常互为近邻：5 天异常 LOF≈1 漏检 | 缩短到 3 天（对齐真实突跳口径） |
| 4 | 工作阈值：98.7% 分位下漏检 | 阈值由敏感性分析确定，不拍脑袋 |

**冒烟测试的价值**：在用真实数据之前，用合成数据（植入已知异常）验证整条链路能跑通。出错一定是代码 bug，排查简单。

## 七、核心结果

### 7.1 模型对比

| 模型 | RMSE | R² | 说明 |
|------|------|------|------|
| naive（持久性） | 0.1860 | 0.5988 | 下界 |
| RF | 0.1850 | 0.6031 | 文献配置 |
| LSTM | 0.1822 | 0.6150 | 文献配置 |
| LSTM-RF | 0.1715 | 0.6589 | 文献最优 |
| **CNN-LSTM** | **0.1675** | **0.6748** | **本项目主模型** |

CNN-LSTM 比 LSTM-RF 的 R² 高 0.062，RMSE 降低 8.4%——卷积层的局部特征提取带来了实证增益。

### 7.2 异常检测结果

3 个异常事件，全部通过三道关：

| 事件 | 时段 | 气象 | 地震对应 | 判定 |
|------|------|------|----------|------|
| 1 | 2024-03-22~03-28 | 降水7.9mm ✓ | 19个M4+，3个M5+ | ✓ 潜在构造 |
| 2 | 2024-04-06~04-09 | 降水0mm ✓ | 21个M4+，2个M5+ | ⚠️ 需辨析震前/同震 |
| 3 | 2024-11-16~11-21 | 降水1.7mm ✓ | 12个M4+ | ✓ 潜在构造 |

⚠️ 事件 2 的时间范围内包含 M5.0 昭通地震本身，需区分震前响应与同震响应。
